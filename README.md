# Журнал смен

Электронный журнал смен вместо Excel: SQLite + FastAPI + веб-интерфейс.

## Запуск

```
uv run uvicorn app.main:app --port 8000
```

Открыть в браузере: http://localhost:8000

База данных создаётся автоматически в файле `journal.db` в корне проекта
(путь можно переопределить переменной окружения `JOURNAL_DB_PATH`).
Для резервной копии достаточно скопировать этот файл.

## Пользователи и вход

Вход по имени пользователя и паролю; сессия хранится в cookie
`journal_session` (30 дней). При первом запуске на пустой базе создаётся
администратор по умолчанию **admin / admin** — смените пароль после входа.
Администратор управляет пользователями (добавление, смена пароля и роли,
удаление), а также редактирует группы обхода и макет печати.

## Деплой (Docker + nginx)

```
docker compose up -d --build
```

Открыть в браузере: http://localhost (порт 80).

- `app` — FastAPI под uvicorn (порт 8000, наружу не публикуется);
- `nginx` — принимает порт 80, раздаёт статику из `app/static` напрямую
  и проксирует остальные запросы (API) в приложение;
- `backup` — еженедельный бэкап базы (`scripts/backup.py`): `VACUUM INTO`
  в папку `./backups` на хосте с ротацией старых копий (хранится 8 последних,
  настраивается переменной `JOURNAL_BACKUP_KEEP`);
- база лежит в именованном томе `journal-data` (`/data/journal.db` внутри
  контейнера). При первом запуске (том пустой) туда копируется `journal.db`
  из репозитория — деплой стартует с заполненными данными; дальнейшие
  пересборки и перезапуски базу в томе не трогают. Резервная копия вручную:
  `docker compose cp app:/data/journal.db ./journal.db.bak`.
  Начать заново с базы из репозитория: `docker compose down -v`
  (удаляет том вместе с накопленными данными), затем `up -d --build`.

## Миграции

Схема базы управляется Alembic. При старте приложение само доводит базу до
актуальной версии (`alembic upgrade head`), базы, созданные до внедрения
Alembic, автоматически помечаются базовой ревизией.

После изменения моделей в `app/db/models.py`:

```
uv run alembic revision --autogenerate -m "описание изменения"
uv run alembic upgrade head
```

Полезные команды: `alembic current` — текущая ревизия базы,
`alembic check` — проверка, что модели не разошлись с миграциями.

## Как пользоваться

1. На главной странице — календарь года (стрелками ‹ › можно переключать год).
   Точки под датой показывают заполненные смены: жёлтая — дневная, синяя — ночная.
2. Клик по дате → выбор смены (день / ночь).
3. Открывается отчёт по смене:
   - данные смены: время начала и конца, фамилия дежурного, обозначение смены;
   - отключения и переключения: тип, время, место, причина;
   - оборудование на обходе: в новом отчёте подставляются участки текущей
     группы обхода (номер определяется графиком), но можно добавить и любой
     другой участок, если по нему есть замечание;
   - происшествия: период времени, участок, оборудование, описание неисправности,
     код детали, количество.
4. Кнопка «Сохранить отчёт» записывает всё в базу. «Удалить отчёт» убирает смену целиком.
5. Страница «Группы обхода» — все участки разбиты на 8 групп: одна группа
   обходится за дневную + ночную смену, за месяц дежурный обходит все группы.
   Состав групп можно редактировать (при первом запуске заполняется по умолчанию).
   Номер группы определяется графиком: цикл 8 дней, каждый день группа
   сдвигается на одну; у дневных и ночных смен свои смещения, поэтому у соседних
   смен группы всегда разные. Опорная дата 13.07.2026: в день — группа 6,
   в ночь — группа 4.

## Структура

Приложение разбито на слои: маршруты → сервисы → репозитории → модели.

- `app/main.py` — точка входа FastAPI: статика, middleware, подключение роутеров
- `app/api/v1/` — REST-маршруты (смены, отключения, происшествия, участки,
  группы обхода, пользователи, авторизация, макет печати)
- `app/api/deps.py` — зависимости FastAPI (сессия БД, текущий пользователь, админ)
- `app/services/` — бизнес-логика
- `app/repositories/` — доступ к данным (SQLAlchemy 2.0 ORM)
- `app/db/` — модели (`models.py`), подключение (`session.py`),
  инициализация базы и сиды (`base.py`)
- `app/schemas/` — Pydantic-схемы запросов/ответов
- `app/core/` — настройки (`config.py`), пароли и токены сессий (`security.py`)
- `app/static/` — веб-интерфейс (HTML/CSS/JS без фреймворков)
- `alembic/` — миграции схемы базы
- `scripts/` — служебные скрипты:
  - `backup.py` — демон еженедельных бэкапов (сервис `backup` в docker-compose);
  - `extract_old_journals.py` / `import_old_journals.py` — разбор старых
    Excel-журналов в `old_journals.json` и импорт их в базу (уже существующие
    смены пропускаются)
